## 3. Contracts delivered
- **Trace contract**: every request produces server -> service -> JDBC spans; events crossing the fabric add `squamed.realtime.relay` spans tagged `squamed.event.type`; sampling delivers the spec's 10% normal / 100% error via head sampler `parentbased_traceidratio=1.0` + collector tail_sampling (ERROR traces kept 100%, probabilistic 10% baseline) - error traces are never lost to the coin flip.
- **Metrics contract**: `http_server_requests_seconds` with buckets (RED), JVM base, and business counters/gauges: `squamed_events_dispatched_total{type}`, `squamed_ws_relayed_total{type}`, `squamed_ws_sessions`, `squamed_events_dlq_total{type}`, `squamed_events_dlq_depth`, `squamed_events_pending`, `squamed_integration_errors_total`, `squamed_sla_breaches_total{priority}`, `squamed_audit_chain_breaches`, `squamed_audit_chain_seconds_since_verify` (Micrometer dots -> Prometheus underscores; counters gain `_total`).
- **Alert contract**: the three on-call alerts the section row names are live and load in Prometheus (SLO burn, audit-chain breach, DLQ non-empty > 15 min) plus 4 supporting alerts; each links its runbook anchor.
- **Dashboard contract**: Grafana auto-provisions the Prometheus datasource and the RED dashboard (module variable) on container start - no manual import.
- **PIT seam contract**: `ObservabilitySpanCapture` exposes in-memory spans deterministically via the SDK SPI; metrics verification goes through the real `/actuator/prometheus` scrape (no meter-registry shortcut), so the tests assert exactly what ops sees.
- NOT delivered (documented deviations, section 9): failover-event and cert-expiry alerts; structured-JSON logs + PHI-scrubber line of spec section 3 (not part of the 00.16 row).

## 7. Issues found during build
- **Boot 3.3.5 BOM pins otel 1.37.0, starter 2.10.0 needs 1.44.1**: the starter pulled mismatched API versions (NoSuchMethodError at boot). Fix: explicit `opentelemetry-bom(-alpha) 1.44.1` imports in `dependencyManagement`; verified resolution with `:dependencyInsight`.
- **OTLP protocol default mismatch**: the starter defaults to `http/protobuf` (:4318) while the compose collector was wired for grpc :4317 - spans silently failed to export. Fix: explicit `otel.exporter.otlp.protocol: grpc`.
- **Boot disables metrics export in every `@SpringBootTest`** (`ObservabilityContextCustomizerFactory` sets `management.defaults.metrics.export.enabled=false`) - the scrape endpoint serves nothing in tests. Fix: `systemProperty("spring.test.observability.auto-configure", "true")` on the `integrationTest` task, inside the existing `tasks.register<Test>("integrationTest")` block.
- **Per-class `@AutoConfigureObservability` forks a second full Spring context** (different context-cache key): the PIT JVM then runs two apps - the second context's `EventDispatcher` steals outbox rows and its registry is never scraped, so dispatched-counter assertions flapped across runs 4-7 (one registry visible, two `scheduling-*` threads). Fix: drop the annotation entirely; the systemProperty alone unifies all contexts (same cache key -> single app). Lesson: observability test config belongs in build config, not annotations, when the suite shares one context.
- **Counter registration timing**: Micrometer emits a series only after the first increment - the SLA breach counter does not exist until a breach happens. The PIT drives a real overdue task (dueAt 2020) through `POST /api/v1/tasks/sla/scan` instead of pre-registering a 0-meter (which would lie about the metric's semantics).
- **Gauge baseline vs dirty DB**: prior failed PIT runs left tampered tenants in the audit DB; the breaches gauge reads 0.0 until the first verify runs in the JVM, then jumps. The test establishes the baseline with a real verify before reading b0.
- **Frame/span selection precision**: substring event-frame counting matched `notification.dispatched` payloads that embed `task.created`; blind `.last()` on relay spans picked a later event's relay. Fixes: JSON-parsed `isEventFrame()` helper with full-frame dump on failure; span selection filtered by the `squamed.event.type` attribute.
- **Demo tamper hit the SYSTEM chain (root-caused)**: the demo tampered the newest audit row and the breach gauge stayed 0 - platform-admin writes carry `hospital_id` NULL, so their audit rows land in the SYSTEM chain, which the verifier explicitly skips (`breachedTenants` counts *tenants*). Every tenant chain row must come from a hospital-bound actor; the PIT already registered a doctor in a fresh hospital for exactly this reason. Demo now mirrors the PIT (fresh hospital + doctor patient write + baseline verify + exact +1/-1 delta).
- **Grafana provisioning race**: the first demo round queried `/api/datasources` while a just-recreated Grafana was still provisioning - the dashboard check passed seconds earlier, the datasource check did not. Fixed with a bounded retry (6x5s).
- **Windows PowerShell 5.1 trap**: `docker compose` writes progress to stderr; under `powershell.exe` + `$ErrorActionPreference='Stop'` + `2>&1` every progress line becomes a terminating `NativeCommandError`. Demo scripts must run under pwsh 7 (native stderr is no longer error-rewrapped there). Also: the demo now tree-kills the 8081 owner at exit - without that cleanup the wrapper pwsh lingered past the summary.

## 9. Deviations from chunk file
- **Failover-event and cert-expiry alerts not implemented** (spec section 3 line 32 lists them): there is no standby DB/failover event source and no managed-cert fleet at dev scale; the two alerts would page on nothing. Recorded as debt for the HA/production-hardening section; the three alerts the section row actually names are live.
- **Logs line of spec section 3 (structured JSON, PHI scrubber at ship time, 30d/1y retention)** is not part of the 00.16 section row; stdout logging is unchanged from the earlier sections.
- **Sampling shape**: head sampler runs at 1.0 + collector tail_sampling implements "10% normal / 100% error" - net behavior matches the spec, but the split lives in the collector (single place to tune per-environment), not the SDK.
- **Prometheus endpoint is unauthenticated** (permitAll): it serves RED/JVM/business metrics only - counters and gauges, no identifiers, no PHI - and is scrape-only (not in the JWT-protected API surface). Authenticated scraping would require a bearer-token story in the Prometheus scraper config; noted as a production-hardening item.
- **One RED dashboard with a module variable** rather than dashboards-per-module: same coverage, one artifact to maintain.
- **Alert delivery sink is per-deployment wiring**: alertmanager routes (default + critical) point at `host.docker.internal:9095` webhooks with a comment noting the real receivers (Slack via env, prod compose). Nothing listens on :9095 at dev scale, so AM logs notify-retry noise when an alert fires - expected; the alert evaluation/routing rules themselves are what this section delivers.
