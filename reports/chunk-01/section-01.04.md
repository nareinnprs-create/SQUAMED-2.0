- **`encounter/service/EncounterService.kt`** — extended with the clinical-safety core:
  - **Allergy gate on every Rx** (CS-02/CS-03): patient's active allergies normalized (lowercase/trim); **BLOCK = exact token equality** with the drug name → 409 `ALLERGY_BLOCK`; **WARN = substring either direction with both lengths ≥ 4** → rejected with 409 `ALLERGY_WARN_REASON_REQUIRED` unless a typed `overrideReason` is supplied — overridden Rx saves `overrideReason` + `allergy_status='warn_override'` and increments the KPI counter `squamed.rx.allergy.warn.overrides` (exported as `squamed_rx_allergy_warn_overrides_total`); clean Rx records `allergy_status='checked'`.
  - **CS-01 two-identifier confirm** on prescriptions **and** encounter orders: `patientMrn` must be present and match the encounter's patient → 400 `PATIENT_MISMATCH` otherwise (screen-must-confirm-the-patient rule).
  - **Note signature**: `method=PIN` requires a 4+ digit PIN (unsalted SHA-256 hex into `signature_data` — short-cut vs a KDF/HSM, code-commented) and `method=ESIGN` requires the `esignTransactionId` from the 00.12 eSign substrate; missing credentials → 400 (`SIGNATURE_PIN_REQUIRED` / `ESIGN_TRANSACTION_REQUIRED`); re-sign → 409 `NOTE_ALREADY_SIGNED` (immutable once signed).
  - **Coded diagnosis**: unknown code → 400 `DIAGNOSIS_CODE_UNKNOWN`; a blank name is filled from the catalog display and the saved `system` is the canonical catalog `system` (no free-text drift).
  - **Procedures** (planned/completed/cancelled + outcome/notes) and **referrals** (department/specialty/facility target required → 400 `REFERRAL_TARGET_REQUIRED`, urgency routine/urgent/emergency, status pending→accepted/completed/cancelled) on the encounter.
  - **Follow-up booking**: delegates to the 01.01 `SchedulingService.book(...)` (reception/admin own slots per V54; the doctor role holds scheduling read only) → **403 for DOCTOR**, and a successful booking stamps `encounter.follow_up_appointment_id`.
  - **Orders**: placing an encounter order emits **`encounter.order.placed`** through the 00.09 transactional outbox (the chunk-2 task engine consumes it — §9).
- **`encounter/api/EncounterController.kt` + `EncounterDtos.kt`** — 7 new endpoints: `GET /encounters/note-templates`, `GET /encounters/diagnosis-catalog`, `POST|GET /encounters/{id}/procedures`, `POST|GET /encounters/{id}/referrals`, `POST /encounters/{id}/follow-up`; the existing `POST /encounters/{id}/orders|prescriptions` and `POST /encounters/notes/{id}/sign` gained the request fields above. Guard errors are 400 message-as-code (`PATIENT_MISMATCH`, `DIAGNOSIS_CODE_UNKNOWN`, `SIGNATURE_PIN_REQUIRED`, `ESIGN_TRANSACTION_REQUIRED`, `REFERRAL_TARGET_REQUIRED`), state guards 409 (`ALLERGY_BLOCK`, `ALLERGY_WARN_REASON_REQUIRED`, `NOTE_ALREADY_SIGNED`); cross-tenant reads/writes → 403 (tenant-scoped repositories).

## 7. Issues found during build + fixes
- **`next/font` failed CI twice in a row** (run 44060989286: `TypeError: Cannot read properties of null (reading '1')` in `nextFontGoogleFontLoader` at 10:02:59Z and 10:07:57Z — build-time Google Fonts fetch drift on the runner, not transient; the 01.03 retry-green precedent did not hold). Fix: **self-hosted the fonts** — the 30 woff2 files from the working local build plus the generated @font-face CSS (verbatim: families, unicode-ranges, size-adjust Fallback faces, `--font-plex-*` variables) vendored into `src/fonts/` + `src/app/fonts.css`; `layout.tsx` no longer imports `next/font/google`, so web builds are network-independent. Local parity: typecheck clean, turbo build 7/7, VRT 9/9 (baselines stable via font-normalize).
- **PIT architecture fact (this section's main discovery)**: `PlatformIntegrationTests` is `@SpringBootTest(webEnvironment = RANDOM_PORT)` — it **always boots its own in-process Spring context**; `SQUAMED_IT_EXTERNAL` only selects the infra (Testcontainers vs compose). Consequence: a running dev `bootRun` app holds MLLP :2575, the PIT context's bind fails *gracefully* (`mllpRunning=false`), and MLLP-dependent PIT checks fail — while everything else runs green, which made it look like a code bug. Rule (now documented here): **kill the dev app before `integrationTest`**; CI never hits this (nothing else binds :2575). Symptom chain diagnosed via the PIT XML reports (`mllpRunning=false` → `Hl7Service.startMllp` catch-block).
- **Six old-test failures after the new contracts** (triaged, all fixed as §5): missing `patientMrn` on 4 Rx/order calls (CS-01 now gates them), empty sign body now 400 (needs PIN), and the event-catalog count assert 20 → 21.
- **Demo invalidated twice by environment, not code**: (1) Docker Desktop engine crash #2 mid-session killed PG/MinIO + the app mid-demo (1 passed / 28 failed run, scrapped); (2) engine crash #3 killed PG again during the next boot (flyway connection refused). Both recovered with the documented sequence (Docker Desktop restart → `docker info` stable ×3 → `docker start squamed-*` → PG healthy → bootRun); Grafana's :3005 bind conflict remains the known non-issue. Final demo run clean.
- **A Gradle daemon death ("daemon disappeared unexpectedly")** after a heavy parallel load (PIT daemon + bootRun + the 7-package web production build at once) killed the first healthy app boot; recovered by stopping daemons and re-booting before the demo.
- **`npm run codegen` at the repo root fails** (missing script) — the documented workspace form is `npm run codegen -w @squamed/api-client` (§2).
- **Playwright `--update-snapshots` takes a mode, not a filter** (`=missing`), and the title filter is a regex on the file path/title — `npx playwright test --config playwright.visual-regression.config.ts --update-snapshots=missing` writes only the new baseline; the suite was then verified green in compare mode.

## 9. Deviations from chunk file
- **Signature methods**: the chunk file names "eSign + PIN fallback". The build ships **PIN as the primary path** (unsalted SHA-256 of the PIN into `signature_data` — a deliberate short-cut vs a KDF/HSM, code-commented) and **ESIGN as the alternative method** that verifies a `esignTransactionId` from the existing 00.12 eSign substrate. No separate eSign ceremony UI in this chunk; the signature is immutable either way (re-sign 409).
- **Follow-up UI deep-links to `/appointments`** rather than an in-consult slot picker: booking stays with reception/admin by permission design (V54 — doctors hold scheduling read only), so the doctor's consult tab surfaces the booked follow-up and links to the appointments workspace where the slot picker already lives (01.01/01.03). The backend `POST /encounters/{id}/follow-up` + stamp is complete.
- **Procedures/referrals/templates/catalog ride existing note permissions** — zero new permission codes; the referral write also accepts `clinical:manage:referral` (existing code, activated).
- **Outbox emit, not the task engine** — `encounter.order.placed` is produced transactionally; consuming it into tracked tasks is the chunk-2 line the spec itself defers.
- **Doctor follow-up denial is 403 by design** (RBAC, `scheduling:write:appointment`) — the demo/PIT assert it as the correct behavior, not a gap.
- **Six old tests updated for the new contracts** (CS-01 MRN on shared-surface Rx/order calls, PIN on the journey sign, catalog count 21) — the shared surfaces got stricter, so the old calls needed the new fields; no assertion was loosened.
- **Event catalog count assert 20 → 21** in the old test — deliberate: the chunk adds `encounter.order.placed`.
