## 7. Issues found during build + fixes
- **CI run 44162724119 FAILED (2 jobs) — fixed, re-run green as 44166436687.**
  - *Integration gates*: `kioskCheckInJourney` NPE at `data(PlatformIntegrationTests.kt:80)` via the mobile check-in call (L8537) — the error envelope had no `data`. Root cause: the three main patients used `"55${System.currentTimeMillis()}".take(12)` — **head-truncation leaves 100 ms resolution**, and on CI's faster runner the pAbha and pPhone creates landed in the same 100 ms bucket → two patients of h1 on the same phone → mobile check-in → `KIOSK_IDENTIFIER_AMBIGUOUS` → 400. Passed locally twice (slower creates crossed the bucket boundary — a real flake, not a service bug). Fix = test-side only: tail tags `A`/`B`/`C` appended before `takeLast(12)` (the tag survives truncation), so same-ms creates stay distinct. Verified locally standalone, then green on CI.
  - *Zero-stub grep*: `workspace.test.tsx:6` `vi.mock('qrcode', …)` matched the banned marker `mock` (test file, genuine module double). Fix = tag the line `// test-fixture` per the house pattern (hospital-selector / universal-search / user-menu).

## 9. Deviations from chunk file

- **OTP-less weak-auth risk accepted at chunk scope** — the kiosk resolves patients by ABHA/mobile without OTP verification (kiosk-lite). The slip carries only the patient's own context; multi-patient phones are rejected as ambiguous. Flagged as a policy decision for the hospital deployment (hardening is a later chunk's surface).
- **Walk-ins unsupported in v1** — no today appointment → `KIOSK_NO_APPOINTMENT` with reception-desk guidance; walk-in registration stays a reception flow (chunk file's kiosk is appointment-based).
